\section{Contexto}

El proyecto \textbf{SalesHealth} parte de un \emph{dataset sintético} del
sector salud y bienestar, distribuido como punto de partida para la
entrega final de la asignatura. El conjunto reproduce el escenario habitual
de una pequeña cadena retail: $50$ productos repartidos en categorías como
\emph{wellness}, \emph{diagnóstico} o \emph{rehabilitación}; una red de
tiendas físicas situadas en distintos barrios; un catálogo de promociones y
un flujo de devoluciones con motivo asociado.

El dataset cubre una ventana temporal de seis años naturales, $2020$ a
$2025$ inclusive, ambos con datos hasta finales de diciembre, lo que
equivale a $72$ meses de actividad. Los datos crudos llegan ya cargados en
el esquema \texttt{public} de una instancia local de PostgreSQL~16
desplegada en Docker y escuchando en \texttt{localhost:5433}.

\section{Objetivos del proyecto}

Los objetivos del enunciado se mapean a los capítulos siguientes:

\begin{enumerate}
  \item Diseñar un \textbf{modelo Entidad--Relación} sobre el esquema
        \texttt{public} y un \textbf{modelo dimensional} en estrella sobre
        \texttt{dwh} (capítulo~\ref{ch:modelo}).
  \item Implementar un \textbf{ETL} reproducible desde los datos crudos
        hasta el DWH, pasando por un área intermedia \texttt{staging}
        (capítulo~\ref{ch:etl}).
  \item Calcular el \textbf{CLTV} por cliente, según la fórmula
        $\mathrm{CLTV} = \text{Ingresos}_t \times \text{Margen}_t \times
        \text{Frecuencia}_t \times R_t$, junto con dos métricas
        adicionales: \emph{Recencia} y \emph{AOV}, así como la tasa
        de devolución (capítulo~\ref{ch:cltv}).
  \item Aplicar \textbf{PCA + KMeans} sobre las métricas anteriores para
        \textbf{segmentar} la base de clientes
        (capítulo~\ref{ch:segmentacion}).
  \item Documentar todo en este \textbf{informe técnico} y exponer los
        resultados en un \textbf{dashboard} interactivo
        (capítulo~\ref{ch:dashboard}).
\end{enumerate}

\section{Stack tecnológico}

El proyecto está implementado con un stack deliberadamente clásico y
reproducible, evitando orquestadores externos:

\begin{itemize}
  \item \textbf{Python 3.11+}, gestionado mediante un entorno \texttt{conda}
        denominado \texttt{UAX}. Todos los comandos del repositorio se
        invocan como \texttt{conda run -n UAX <comando>}.
  \item \textbf{PostgreSQL 16} sobre Docker, accesible en
        \texttt{localhost:5433} y base de datos \texttt{saleshealth}, con
        tres esquemas: \texttt{public} (raw), \texttt{staging} (limpio) y
        \texttt{dwh} (estrella).
  \item Bibliotecas: \texttt{pandas}, \texttt{SQLAlchemy} 2.0,
        \texttt{psycopg2}, \texttt{scikit-learn}, \texttt{joblib},
        \texttt{matplotlib} y \texttt{pyarrow}.
  \item \textbf{Notebooks Jupyter} numerados como orquestador del pipeline
        (sin Airflow, Prefect ni Dagster).
  \item \textbf{Flask} como servidor del dashboard, con vistas HTML
        estáticas generadas a partir de plantillas Python que embeben
        gráficos de \texttt{Plotly.js}.
  \item \texttt{pytest} para las pruebas y \texttt{ruff} para el linting.
\end{itemize}

futuras. El apéndice recoge listados completos del DDL del DWH, del código
